измеряется, доводит посетителя до заявки и объясняет, кто мы и зачем нужны.

## Этап 0. Разблокировать — без этого не работает ничего

Порядок строгий, каждый пункт блокирует следующие.

### 0.1 Доступ к GitLab `[Вы]`
Ввести токен один раз: `git -C ~/Projects/seventy-times-site push origin main`.
Без этого ни одна правка не доходит до сайта.
**Готово, когда:** коммит `4b71030` ушёл в `main`.

### 0.2 Привязать домен `[Вы]` → проверка `[Я]`
Vercel → проект `seventy-times-site` → Settings → Domains → добавить
`seventy-times.com` и `www.seventy-times.com`.
Это **главный блокер индексации**: сейчас каждый canonical и каждый URL
в sitemap ведёт на 404. Google не проиндексирует ни одну страницу.
**Готово, когда:** `seventy-times.com/en` отдаёт 200 и нашу сборку.

### 0.3 Переменные окружения `[Вы]` → проверка `[Я]`
Минимум для работы:
- `ANTHROPIC_API_KEY` — чат Vanessa
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` — заявки в Telegram
- `RESEND_API_KEY` + `LEAD_NOTIFY_EMAIL` — резервный канал заявок на почту
- `ALLOWED_ORIGINS=https://seventy-times.com`

Сейчас форма и чат на проде не работают. Если продажники начнут слать
ссылки до этого пункта — заявки не дойдут.
**Готово, когда:** тестовая заявка пришла в Telegram и на почту.

## Этап 2. Аналитика

Код готов: `TagManager` с Consent Mode v2, `track()`, события
`lead_form_open`, `lead_submit`, `callback_open`, `callback_submit`,
`chat_open`, `chat_lead_captured`, передача UTM в заявку, дедупликация
Pixel и CAPI через общий `eventId`. Нужно только включить.

### 2.1 Завести аккаунты и прописать ID `[Вы]` → `[Я]`
- `NEXT_PUBLIC_GA_ID` — Google Analytics 4
- `NEXT_PUBLIC_GTM_ID` — Tag Manager, если нужен
- `NEXT_PUBLIC_META_PIXEL_ID` — Meta Pixel
- `META_CAPI_ACCESS_TOKEN` — Conversions API, ловит 20–30% конверсий,
  которые теряет браузерный пиксель

### 2.2 Vercel Web Analytics и Speed Insights `[Вы]`
Компоненты уже стоят в layout, нужно включить в настройках проекта.
Даёт реальные Core Web Vitals от живых посетителей, без cookie.

### 2.3 Настроить конверсии `[Я]`
В GA4 отметить `lead_submit`, `callback_submit`, `chat_lead_captured` как
ключевые события. В Meta — `Lead`.

### 2.4 Добавить недостающие события `[Я]`
Для сайта-презентации не хватает:
- `case_view` и `case_cta_click` — какие кейсы читают и после каких пишут
- `contact_click` — нажатия на телефон, WhatsApp, Telegram, почту
- `audit_offer_click` — интерес к платному аудиту
- глубина прочтения кейса — дочитывают ли до цифр

### 2.5 Ссылки для отдела продаж `[Вместе]`
UTM уже доходят до заявки. Нужен шаблон ссылок для продажников:
`?utm_source=outreach&utm_medium=<канал>&utm_campaign=<менеджер>`.
Тогда видно, чья рассылка приводит заявки и какие кейсы открывают
холодные контакты.

## Этап 3. Доверие — то, что проверяет холодный посетитель

### 3.1 Почта домена: SPF и DMARC `[Вы]` → записи готовлю `[Я]`
**Критично для холодной рассылки.** Без SPF письма с `@seventy-times.com`
падают в спам, без DMARC домен можно подделать. Плюс DKIM для Resend —
иначе не работает резервный канал заявок.

### 3.2 Битые контакты `[Вместе]`
- Telegram `@seventytimes` не существует — завести или заменить ссылку
- LinkedIn — заглушка, нужна реальная страница компании

### 3.3 Юрлицо `[Вы]` → вношу `[Я]`
`legalEntity.ts` пустой, `/imprint` показывает заглушку. Для B2B это
вопрос доверия.

### 3.4 Команда `[Вы]` → вношу `[Я]`
Сейчас один человек по имени, без фамилии и фото. Две роли написаны
и ждут подтверждения имён.

### 3.5 Отзывы `[Я]`

хранилище удалено вместе с Notion. Сделать хранилище (Upstash, уже заложен
в `.env.example`) и одобрение одним нажатием из Telegram.
