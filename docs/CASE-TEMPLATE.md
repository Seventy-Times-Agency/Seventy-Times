# Паспорт кейса — Seventy Times

Единый шаблон для всех кейсов. Заполняется один раз на проект, до вёрстки.
Принцип: **не показываем, что мы сделали — показываем, что изменилось.**

Главное правило данных: **ни одна цифра не публикуется без базы, срока и источника.**
`CPL $185 → $67 за 60 дней, источник: Meta Ads Manager` работает.
`+214% лидов` — нет, это лозунг.

---

## Как читать пометки

- **[ОБЯЗАТЕЛЬНО]** — без этого кейс не публикуется
- **[СИЛЬНО]** — резко повышает доверие, собирать всегда, когда возможно
- **[ОПЦИЯ]** — приятно иметь, можно пропустить

---

## БЛОК 1. Результат — первый экран

| Поле | | |
|---|---|---|
| Заголовок-утверждение | [ОБЯЗАТЕЛЬНО] | одно предложение: **что изменилось**, не что сделали |
| Подзаголовок | [ОБЯЗАТЕЛЬНО] | одно предложение: за счёт чего |
| Главная метрика | [ОБЯЗАТЕЛЬНО] | см. формат ниже |
| Ещё 2–3 метрики | [СИЛЬНО] | |

**Формат метрики — пять полей, все обязательны:**

```
показатель:  Cost per qualified lead
было:        $185
стало:       $67
срок:        60 дней
источник:    Meta Ads Manager
```

Плохой заголовок: «Мы настроили рекламу для кровельной компании»
Хороший: «От дорогих лидов к предсказуемой системе привлечения»

## БЛОК 2. Отправная точка

| Поле | | |
|---|---|---|
| Что было у бизнеса до нас | [ОБЯЗАТЕЛЬНО] | 2–4 факта, без оценок |
| Где терялись деньги | [ОБЯЗАТЕЛЬНО] | 1–3 пункта |
| Материалы «до» | [СИЛЬНО] | скриншот старого сайта, старых креативов, кабинета |

Скриншоты «до» собирать **в первый день проекта**. Потом их взять неоткуда:
старый сайт заменён, кабинет перенастроен, доступы отозваны.

## БЛОК 3. Диагноз

| Поле | | |
|---|---|---|
| Как была устроена воронка | [ОБЯЗАТЕЛЬНО] | цепочка шагов от показа до денег |
| Где было узкое место | [ОБЯЗАТЕЛЬНО] | **одно** место, не список |
| Почему именно там | [ОБЯЗАТЕЛЬНО] | одно предложение |

Этот блок отличает нас от исполнителя задач. Он показывает, что мы смотрим
на бизнес как на систему, а не «делаем рекламу».

## БЛОК 4. Что сделали

3–5 решений. Для каждого:

| Поле | | |
|---|---|---|
| Название | [ОБЯЗАТЕЛЬНО] | одно слово: позиционирование, привлечение, конверсия, автоматизация |
| Что конкретно | [ОБЯЗАТЕЛЬНО] | одно предложение |
| Подтверждение | [СИЛЬНО] | скриншот, ссылка, схема |

Больше пяти — значит, не выделено главное.

---

## БЛОК 5. До и после

Пары «было → стало». Для каждой:

| Поле | | |
|---|---|---|
| Что сравниваем | [ОБЯЗАТЕЛЬНО] | сайт, креатив, воронка, процесс |
| Материал «до» | [ОБЯЗАТЕЛЬНО] | файл или ссылка |
| Материал «после» | [ОБЯЗАТЕЛЬНО] | файл или ссылка |

Для сайтов — ползунок сравнения. Для рекламы и систем — две картинки рядом
или схема, ползунок там бесполезен.

## Порог публикации

Кейс можно публиковать, если есть:

1. Блок 0 целиком
2. Заголовок-утверждение
3. **Хотя бы одна метрика со всеми пятью полями**
4. Диагноз — где было узкое место
5. 3–5 решений

Всё остальное усиливает, но не блокирует.

## Если данных нет

Так уже вышло с ранними проектами, и это нормально — но только при честной подаче.

- **Нет метрик вообще** → кейс становится описательным: что делали, когда,
  для кого. Прямо пишем, что данные не сохранились. Именно так сделан кейс
  Буковеля, и это правильно.
- **Есть объём, но нет результата** → показываем масштаб как масштаб
  («~700 моделей авто»), но не выдаём его за бизнес-результат.
- **Клиент не разрешает называться** → обезличиваем до отрасли и гео,
  цифры оставляем.
- **Нет скриншотов «до»** → пара «до/после» не строится, показываем только
  «после».

Описательный кейс — честный кейс. Кейс с выдуманными цифрами — ложь,
которая рано или поздно вскроется на созвоне с клиентом.

## Чек-лист на старте нового проекта

Заполняется **до начала работ**, иначе baseline потерян навсегда.

- [ ] Скриншоты старого сайта, всех страниц воронки
- [ ] Скриншоты рекламных кабинетов за 30–90 дней до старта
- [ ] Текущие значения: CPL, конверсия, объём лидов, выручка
- [ ] Как клиент считает качественный лид
- [ ] Доступы к аналитике зафиксированы
- [ ] Согласовано, что можно публиковать
